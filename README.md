# Salatic — конвертер и редактор файлов

Быстрый и приватный веб‑сервис для преобразования документов, таблиц, презентаций, электронных книг и изображений, а также для их редактирования. Файлы обрабатываются **прямо в браузере** пользователя и никуда не загружаются; сайт и API обслуживаются **Cloudflare Workers**.

## Возможности

### Конвертер

| Из | В |
|---|---|
| **PDF** (в т. ч. защищённые паролем и сканы) | Word (DOCX), OpenDocument (ODT), RTF, EPUB, TXT, Markdown, HTML, PDF с распознанным текстом, PNG/JPG постранично |
| **Word DOCX, Word 97–2003 DOC, OpenDocument ODT, RTF** | PDF, DOCX, ODT, RTF, EPUB, TXT, Markdown, HTML; таблицы документа → XLSX/ODS/CSV |
| **PowerPoint PPTX** | PDF (слайд в слайд), DOCX, ODT, RTF, TXT, Markdown, HTML |
| **EPUB** | PDF, DOCX, ODT, RTF, TXT, Markdown, HTML |
| **Markdown / HTML / TXT** | PDF, DOCX, ODT, RTF, EPUB, HTML/Markdown/TXT; HTML → таблицы |
| **Excel XLSX, Excel 97–2003 XLS, OpenDocument ODS, CSV, TSV, JSON** | друг в друга, а также PDF, DOCX, HTML, Markdown |
| **JPG, PNG, WebP, GIF, BMP, SVG, ICO, AVIF, TIFF (многостраничный), HEIC/HEIF** | PNG, JPG, WebP, BMP, TIFF, ICO, AVIF (если браузер умеет), PDF; распознавание текста → DOCX/TXT |

- Пакетная обработка в пуле Web Worker'ов, «Скачать все» одним ZIP, объединение изображений в один PDF.
- Перетаскивание, выбор файлов, вставка из буфера (Ctrl+V); готовые сценарии «PDF → Word», «PowerPoint → PDF», «DOC → DOCX» и др.
- Параметры: размер страницы (как в документе / A4 / Letter), качество JPG/WebP, DPI, разделитель CSV, режим OCR.
- **Защищённые PDF**: файлы с ограничениями прав открываются сразу, для файлов с паролем появляется запрос пароля (RC4 40/128, AES‑128, AES‑256). Результат сохраняется без пароля — об этом выводится уведомление.

**PDF → Word** восстанавливает структуру, а не «картинку»: абзацы, заголовки, начертания и семейства шрифтов, размеры, списки (включая векторные маркеры), таблицы по рамкам (с объединёнными ячейками) и по выравниванию столбцов, изображения, колонтитулы убираются; **многоколоночные страницы** читаются колонка за колонкой (включая абзацы, перетекающие в соседнюю колонку). Страницы без текстового слоя **распознаются (OCR, русский + английский)**.

**Документ → PDF** — собственная типографская вёрстка: метрически совместимые шрифты (Arial/Times/Courier/Calibri → Liberation/Carlito), автоматическая подстановка шрифтов для любых письменностей (кириллица, греческий, CJK, эмодзи), межстрочные интервалы как в Word, колонтитулы с номерами страниц, сноски внизу страницы, таблицы с переносом по страницам, разрыв абзацев между страницами с контролем висячих строк (не меньше двух строк на каждой странице), **разделы с колонками** (в том числе разной ширины; перетекание текста между колонками и страницами, балансировка перед непрерывным разделом, линии между колонками), **разделы со своим размером и ориентацией страницы** (альбомные страницы среди книжных), **плавающие рисунки с обтеканием** (текст слева/справа от рисунка, «сверху и снизу», рисунки за текстом и перед ним, логотипы и фоновые рисунки колонтитулов), векторные рисунки EMF/EMF+/WMF/SVG (с отсечением, градиентами, узорами и масками) и **диаграммы Office** — как векторы с выделяемым текстом.

**Диаграммы** Word и PowerPoint (гистограммы и линейчатые, графики, области, круговые и кольцевые, точечные и пузырьковые, лепестковые, биржевые, поверхностные, объёмные варианты, вторичная круговая, комбинированные со второй осью) рисуются по сохранённым в файле значениям в стиле Office: «круглые» шкалы осей, подписи данных, легенда, цвета темы, числовые форматы. При сохранении в DOCX диаграмма остаётся **настоящей диаграммой Word** (её можно редактировать), в RTF — векторным рисунком.

### Редакторы

- **Редактор PDF** — объединение PDF и изображений, перестановка, поворот, дублирование, удаление и извлечение страниц, разделение на файлы; **правка существующего текста страницы** (щелчок по строке → исправление; подбираются шрифт, размер, начертание и цвет; старая строка **удаляется из файла**, остальной текст не сдвигается); **«Скрыть данные»** — настоящее редактирование конфиденциальных сведений: текст (включая невидимый слой OCR и вертикальный CJK), векторная графика, пиксели изображений любых форматов PDF (JPEG, JPEG 2000, JBIG2, CCITT, Flate/LZW и цепочки фильтров) вместе с их масками прозрачности, ссылки и поля форм под прямоугольником удаляются из PDF безвозвратно, область закрашивается; миниатюры страниц, служебные данные приложений и название документа в результат не попадают; добавление текста, «замазка» (тоже удаляет текст под собой), маркер, рисование, изображение/подпись; отмена.
- **Редактор изображений** — обрезка с пропорциями, поворот, отражение, изменение размера, яркость/контраст/насыщенность, фильтры, кисть, надписи, отмена/повтор, экспорт в PNG/JPG/WebP/AVIF/BMP/TIFF/ICO. Открывает и TIFF/HEIC.
- **Редактор документов** — открывает DOCX, DOC, ODT, RTF, EPUB, PPTX, PDF, Markdown, HTML, TXT, таблицы; шрифты и размеры, выделение цветом, сноски, колонтитулы с номерами страниц, списки, таблицы, изображения, ссылки, разделы с колонками; диаграммы сохраняются при правке; автосохранение черновика; сохранение в DOCX, PDF, ODT, RTF, HTML, Markdown, TXT.

### Расшифровка аудио и видео

Страница **«Расшифровка»** (`/transcribe`) превращает запись разговора в текст с разделением на спикеров и метками времени.

- **Источник:** файл аудио или видео (MP3, M4A, WAV любых разрядностей, OGG/Opus, FLAC, MP4, MOV, WebM — всё, что умеет воспроизводить браузер, до 2 ГБ) или ссылка: прямая на файл, Яндекс.Диск, Google Диск, Dropbox. Ссылки на YouTube, VK, RuTube и другие видеохостинги не поддерживаются: эти сайты не отдают файлы, — видео нужно скачать и загрузить файлом.
- **Приватность:** распознавание идёт **в браузере** (WebGPU, иначе многопоточный WebAssembly); запись не покидает устройство. Модели скачиваются один раз с Hugging Face и хранятся в кэше браузера.
- **Скорость:** с видеокартой (WebGPU) Whisper декодирует запись четырьмя «дорожками» сразу: запись делится на 4 части, и за один проход декодера идут куски всех четырёх частей одним пакетом (шаг декодера на видеокарте стоит почти одинаково для одного куска и для четырёх). Каждый кусок, кроме первого в своей дорожке, получает текст предыдущего куска, как и при поочерёдном распознавании. Поиск спикеров идёт одновременно во втором потоке (сегментация на процессоре, голосовые отпечатки на видеокарте); звук общий для обоих потоков (`SharedArrayBuffer`, без копий). Пакетное декодирование даёт тот же текст, что и поштучное (17 кусков разговоров — 17 совпадений; время слов сверяет `npm run eval:speech -- speech-speed`). Без видеокарты всё идёт по очереди на процессоре. Страница запоминает фактическую скорость на устройстве и заранее показывает ожидаемое время. Замер на процессоре (4 ядра, нативный ONNX Runtime, `SPEECH_MINUTES=10 npm run eval:speech -- speech-speed`): 10 минут разговора трёх дикторов — 342 с (0,56 от длины записи: распознавание 304 с, голосовые отпечатки 29 с, сегментация 9 с).
- **Распознавание:** Whisper large‑v3‑turbo с пословными метками времени. Чтобы ошибок было меньше: модель слушает только участки с речью (на тишине и музыке Whisper «сочиняет» текст вроде «Субтитры сделал DimaTorzok»), куски режутся в паузах, а не через каждые 30 с; каждому куску даётся подсказка — образец пунктуации и конец предыдущего куска (единое написание имён), а также необязательный список **имён и терминов** от пользователя; известные галлюцинации и зацикливания вычищаются.
- **Спикеры:** схема pyannote 3.1 с теми же моделями (сегментация 3.0 и голосовые отпечатки WeSpeaker ResNet34): скользящие окна по 10 с, отпечаток каждого голоса в окне, иерархическая кластеризация, оценка числа одновременных говорящих. Число спикеров определяется автоматически или задаётся. Слова получают спикера по меткам времени, граница реплики не разрывает предложение.
- **Результат:** реплики с цветными метками спикеров; спикеров можно переименовать, реплику — передать другому спикеру, текст — исправить; щелчок по времени запускает запись с этого места. Экспорт: **Word (DOCX)**, текст, субтитры **SRT** и **WebVTT** (с голосами), Markdown, JSON; передача в редактор документов (оттуда — PDF, ODT, RTF). Черновик сохраняется в браузере.
- **Точность** (измерено `npm run eval:speech` на настоящей речи, 50 фраз FLEURS и Russian LibriSpeech): вариант «Максимальная» — WER 5,9 %, CER 1,8 %; «Высокая» — WER 6,2 %, CER 1,8 % (большая часть оставшихся расхождений — числа цифрами вместо слов и архаизмы в стихах Пушкина); в разговорах из записей 2, 3 и 4 разных дикторов число спикеров найдено верно во всех случаях, слова отнесены к своему спикеру в 100 %, 97 % и 100 % случаев. Подсказка‑образец снизила WER с 7,8 % до 6,2 % и убрала куски без заглавных букв и знаков препинания.

## Архитектура и выбор технологий

**Язык — TypeScript** (строгий режим) во всех частях: браузер, Web Worker, Cloudflare Worker и тесты используют один и тот же код ядра.

- **Скорость определяется тем, где идёт работа.** Обработка в браузере исключает загрузку файла на сервер и скачивание результата. Тяжёлые операции выполняет нативный код браузера (кодеки, Canvas, WebCrypto) и WebAssembly (HarfBuzz для подмножеств шрифтов, Tesseract для OCR, libheif для HEIC), всё — в Web Worker'ах, интерфейс не блокируется.
- **Cloudflare Workers** запускают код в изолятах V8 без «холодного старта»; статика раздаётся из кэша CDN, не вызывая скрипт.
- Сервер выполняет только лёгкие преобразования (см. API): лимиты Workers (CPU‑время, память) не подходят для PDF‑вёрстки и OCR.

```
Браузер
 ├─ UI (vanilla TS, без фреймворка)   — стартовый скрипт ≈ 6 КБ gzip, страницы грузятся лениво
 ├─ Пул Web Worker'ов                  — документы, таблицы, PDF, расшифровка, TIFF/HEIC
 │   └─ ядро src/core                  — модули подгружаются только когда нужны
 ├─ OCR (tesseract.js, свои модели)    — сканы и фото → текст, PDF с текстовым слоем
 └─ Canvas                             — изображения, PDF → PNG/JPG, редакторы
Cloudflare Worker
 ├─ Static Assets (+ _headers: CSP, кэш immutable)
 └─ /api/* — health, formats, convert (текстовые, офисные и табличные форматы)
```

Ядро построено вокруг промежуточных моделей (`src/core/model.ts`, `src/core/slides.ts`): читатели превращают байты в `Doc` (поток блоков), `Workbook` (таблицы) или `Deck` (слайды), писатели — обратно. N входных × M выходных форматов не требуют N·M конвертеров.

| Модуль | Назначение |

| `readers/pdf.ts` | PDF → Doc: строки, абзацы, заголовки, списки, таблицы, изображения, колонки |
| `readers/docx.ts`, `writers/docx.ts` | OOXML: стили, темы, нумерация, таблицы, сноски, колонтитулы, изображения |
| `cfb.ts`, `readers/doc.ts`, `readers/xls.ts` | контейнер OLE2, Word 97–2003 (MS‑DOC), Excel 97–2003 (BIFF8) |
| `readers/odf.ts`, `writers/odf.ts` | OpenDocument ODT/ODS: цепочки стилей, списки, таблицы, сноски, мастер‑страницы |
| `readers/rtf.ts`, `writers/rtf.ts` | RTF: кодовые страницы, списки Word и WordPad, таблицы, поля, сноски, рисунки |
| `readers/pptx.ts`, `writers/slides-pdf.ts` | PowerPoint: тема, мастер/макеты/плейсхолдеры, фигуры, группы, таблицы, градиенты → PDF |
| `chart.ts`, `drawingml.ts` | диаграммы Office (c:chartSpace) → SVG; цвета и градиенты DrawingML |

| `readers/epub.ts`, `writers/epub.ts` | EPUB 2/3 |
| `writers/pdf.ts`, `pdf-fonts.ts`, `hb-subset.ts` | вёрстка PDF, подстановка шрифтов, подмножества через HarfBuzz |
| `metafile.ts` | интерпретатор EMF/WMF → векторы для PDF, SVG для веб‑форматов |
| `pdf-decrypt.ts`, `crypto.ts` | Standard Security Handler PDF (MD5, RC4, AES; SHA‑2 через WebCrypto) |

## Запуск

Требуется Node.js ≥ 22.13.

```bash
npm install
npm run dev        # разработка: http://localhost:5173 (Vite)
npm run preview    # сборка + локальный Cloudflare Worker (wrangler dev): http://localhost:8787
```

## Развёртывание на Cloudflare Workers

```bash
npx wrangler login   # один раз
npm run deploy       # сборка и публикация
```

Настройки — в `wrangler.jsonc`: статика из `dist/`, SPA‑маршруты отдают `index.html`, Worker вызывается только для `/api/*`. Заголовки безопасности и кэширования — в `public/_headers`.

## API

Сервер конвертирует форматы без вёрстки: **DOCX, DOC, ODT, RTF, EPUB, PPTX (как текст), Markdown, HTML, TXT, CSV, TSV, JSON, XLSX, XLS, ODS** (до 10 МБ). PDF и изображения обрабатываются в браузере — API отвечает `422` с подсказкой.

```bash
curl https://<host>/api/health
curl https://<host>/api/formats            # форматы и доступные преобразования

# тело запроса — файл; формат источника определяется автоматически
curl -X POST --data-binary @report.doc "https://<host>/api/convert?to=docx&name=report.doc" -o report.docx

# или multipart/form-data с полем file
curl -X POST -F "file=@sales.xls" "https://<host>/api/convert?to=csv" -o sales.csv
```

Ответ — файл с `Content-Disposition` (кириллические имена поддерживаются); предупреждения — в заголовке `X-Warnings` (JSON, URL‑encoded). Ошибки — JSON `{ "error": "...", "code": "..." }` с кодами 400/405/413/415/422/500. CORS открыт.

## Тестирование

```bash
npm test           # модульные и интеграционные тесты ядра (Vitest)
npm run test:e2e   # E2E в Chromium против собранного сайта под wrangler dev
npm run check      # сборка + все тесты
npm run eval:speech  # точность расшифровки на настоящей речи (долго, ~1 ГБ моделей)
```

Для `eval:speech` нужны данные в каталоге `$SPEECH_DATA`: `fleurs/dev.tsv` и распакованный `fleurs/x/dev/*.wav` (FLEURS ru_ru, dev) и `ruls/x/*.wav` + `ruls/x/index.json` (тестовая часть Russian LibriSpeech). Переменные: `SPEECH_PRESET` (`accurate`, `balanced`, `fast`), `SPEECH_N` (число фраз), `SPEECH_OUT` (файл отчёта), `SPEECH_PLAIN=1` (без подсказок — для сравнения), `SPEECH_BATCH=4` (разговоры распознаются пакетами, как на видеокарте в браузере). Скорость и совпадение пакетного декодирования с поштучным: `npm run eval:speech -- speech-speed` (`SPEECH_MINUTES` — длина разговора). Модели скачиваются с Hugging Face (в среде с прокси Node нужен `NODE_USE_ENV_PROXY=1`).

- **Модульные/интеграционные тесты (Vitest)** — полная матрица преобразований и проверка результатов **независимыми программами**: LibreOffice открывает наши DOCX/ODT/RTF/ODS и сам создаёт входные DOC/XLS/ODT/RTF/PPTX/EMF/WMF; poppler (`pdftotext`, `pdftoppm`, `pdffonts`) читает и растеризует наши PDF; pypdf шифрует тестовые PDF (RC4/AES), Pillow создаёт TIFF с разными сжатиями, ffmpeg/x265 — настоящий HEIC; координаты текста слайдов сверяются с рендером LibreOffice; примитивы шифрования — с Node crypto. Плюс «враждебные» входы: zip‑бомбы, глубокая вложенность, повреждённые и обрезанные файлы, огромные таблицы.
- **E2E (Playwright, 24 сценария)** — API и заголовки безопасности; конвертер (DOCX/DOC/ODT/RTF/EPUB/PPTX/XLS, многостраничный TIFF, HEIC, PDF с паролем и его запросом, OCR, пакетная обработка); все три редактора, включая правку текста PDF (старая строка исчезает из текстового слоя) и скрытие данных с JPEG‑фото и изображением JPEG 2000 (декодер WebAssembly в браузере); расшифровка настоящего диалога двух дикторов из видео MP4 (два спикера, порядок реплик, доля ошибок в словах, переименование, экспорт TXT/SRT/DOCX, черновик); мобильная вёрстка.
- Вёрстка сверяется с LibreOffice попиксельно и по координатам слов: колонки (в том числе неравные), страницы разного размера, обтекание рисунков, градиенты слайдов (цвета в пределах 10/255), диаграммы, отсечение в EMF, рисунки EMF+; узоры и маски SVG сверяются с Chromium (расхождение не больше 0,1 % пикселей); удаление текста проверяется на PDF из нашей вёрстки, LibreOffice и Chromium — удалённые слова исчезают, остальные не сдвигаются ни на 0,05 pt; вертикальный текст — по растру poppler.
- Тесты, которым нужны LibreOffice, poppler, python3 или ffmpeg, пропускаются, если программы нет. Для E2E на своей машине: `npx playwright install chromium`. `BASE_URL=https://<host> npm run test:e2e` — прогон против развёрнутого сайта.

## Ограничения

Честный список того, что пока не воспроизводится или воспроизводится приближённо:

- **PDF → Word** остаётся восстановлением структуры по эвристикам: сложные таблицы без рамок и без выровненных столбцов, плавающие надписи и текст по контуру могут потребовать ручной правки.
- **Word → PDF**: обтекание «по контуру» и «сквозное» выполняется по прямоугольнику рисунка; при обтекании «с обеих сторон» текст ставится с более широкой стороны; плавающие рисунки внутри таблиц, сносок и разделов с колонками ставятся в поток; надписи (текстовые поля) и WordArt выводятся обычными абзацами после своего абзаца; вместо фирменных шрифтов используются метрически совместимые свободные аналоги. RTF не хранит плавающие рисунки — они записываются в поток текста.
- **Диаграммы** рисуются по сохранённым в файле значениям — их пишут Word, PowerPoint и LibreOffice.
- **PowerPoint → PDF**: SmartArt — только если в файле есть его готовое изображение; анимации и переходы не переносятся.
- **SVG**: фильтры (тени, размытие) не применяются — элемент рисуется без эффекта; маски передаются как отсечение (полупрозрачные и градиентные маски дают резкий край); маркеры линий (стрелки) не рисуются. **EMF/WMF**: растровые операции, кроме копирования, не применяются. **EMF+**: регионы, текстурные кисти и градиенты по контуру (используется их цвет), вложенные метафайлы не рисуются; файлы с обоими наборами записей рисуются по GDI‑записям.
- **Правка текста PDF**: страница не переверстывается — новый текст длиннее старого может наехать на соседний (редактор предупреждает). **Скрытие данных**: векторные фигуры, лишь пересекающие границу области, остаются под закраской; текст, нарисованный не шрифтом, а контурами, удаляется вместе с фигурами, лежащими целиком в области.
- Не поддерживаются: старые презентации `.ppt`, PDF, зашифрованные сертификатом (не паролем), книги с DRM.
- **Расшифровка:** час записи за 5–15 минут возможен только с видеокартой через WebGPU (актуальные Chrome и Edge на компьютере); скорость на настоящей видеокарте в среде разработки не измерялась — путь WebGPU проверен на программном адаптере (SwiftShader) на правильность, не на скорость. Без WebGPU распознавание идёт на процессоре: на 4 ядрах — около 0,56 от длины записи в нативном замере (час — около 34 минут), в браузере медленнее; на телефонах — очень долго. Первый запуск скачивает модели (≈0,8–1,6 ГБ). Когда говорят одновременно, слова достаются одному из говорящих. Музыка и сильный шум снижают точность. Запись целиком декодируется в память: до 2 ГБ файла и примерно 3–4 часов звука. Видео с YouTube, VK и других видеохостингов по ссылке не скачиваются.
- Нужен современный браузер (актуальные Chrome/Edge/Firefox/Safari): module‑воркеры, OffscreenCanvas, WebAssembly, WebCrypto.
