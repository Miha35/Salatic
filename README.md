# Salatic — конвертер и редактор файлов

Быстрый и приватный веб‑сервис для преобразования файлов (PDF ↔ Word, изображения, таблицы, текстовые форматы) и их редактирования. Файлы обрабатываются **прямо в браузере** пользователя и никуда не загружаются; сайт и API обслуживаются **Cloudflare Workers**.

## Возможности

### Конвертер

| Из | В |
|---|---|
| **PDF** | Word (DOCX), TXT, Markdown, HTML, PNG, JPG (каждая страница; несколько страниц — ZIP) |
| **Word (DOCX)** | PDF, TXT, Markdown, HTML, Excel/CSV (таблицы документа) |
| **Markdown / HTML / TXT** | PDF, Word, HTML/Markdown/TXT; HTML → Excel/CSV (таблицы) |
| **Excel (XLSX) / CSV / TSV / JSON** | друг в друга, а также PDF, Word, HTML, Markdown |
| **JPG, PNG, WebP, GIF, BMP, SVG, ICO, AVIF** | PNG, JPG, WebP, BMP, ICO, AVIF (если браузер умеет), PDF |

- Пакетная обработка (параллельно в нескольких потоках), «Скачать все» одним ZIP, объединение нескольких изображений в один PDF.
- Перетаскивание, выбор файлов, вставка из буфера (Ctrl+V); готовые сценарии «PDF → Word», «JPG → PDF» и др.
- Параметры: размер страницы (A4/Letter), качество JPG/WebP, DPI для PDF → изображения, разделитель CSV («;» для русского Excel).
- Понятные сообщения об ошибках: старые `.doc/.xls`, зашифрованные и повреждённые файлы, документы без таблиц и т. п.

**PDF → Word** восстанавливает структуру, а не «картинку»: абзацы (склейка строк и переносов), заголовки по размеру шрифта, жирный/курсив по именам шрифтов, маркированные и нумерованные списки (включая маркеры, нарисованные векторно), таблицы по линиям рамок (с объединёнными ячейками) и по выравниванию столбцов, блоки кода, изображения, удаление колонтитулов и номеров страниц. Сканы без текстового слоя переносятся изображениями (OCR не выполняется).

### Редакторы

- **Редактор PDF** — объединение нескольких PDF и изображений, перестановка страниц перетаскиванием, поворот, дублирование, удаление, пустые страницы, извлечение выбранных страниц, разделение на отдельные файлы; пометки на странице: текст, «замазка» (закрашивание), выделение маркером, рисование, вставка изображения/подписи; перемещение, изменение размера, отмена.
- **Редактор изображений** — обрезка (свободно / 1:1 / 4:3 / 3:2 / 16:9 / 9:16), поворот, отражение, изменение размера, яркость/контраст/насыщенность, Ч/Б, сепия, негатив (с предпросмотром), рисование кистью, надписи, отмена/повтор, экспорт в PNG/JPG/WebP/AVIF/BMP/ICO.
- **Редактор документов** — открывает DOCX, PDF, Markdown, HTML, TXT, CSV/XLSX; форматирование (заголовки, жирный/курсив/подчёркивание/зачёркивание, цвет, списки, выравнивание, ссылки, таблицы, изображения, линии, разрывы страниц); безопасная вставка из буфера; автосохранение черновика; сохранение в Word, PDF, HTML, Markdown, TXT.

## Архитектура и выбор технологий

**Язык — TypeScript** (строгий режим) во всех частях: браузер, Web Worker, Cloudflare Worker и тесты используют один и тот же код ядра.

Почему так, а не, например, Rust/WASM или серверная конвертация:

- **Скорость для пользователя определяется не языком, а тем, где идёт работа.** Обработка в браузере исключает загрузку файла на сервер и скачивание результата — для документов в несколько мегабайт это быстрее любого серверного решения. Самые тяжёлые операции выполняет нативный код браузера (кодеки изображений, Canvas) и оптимизированный pdf.js.
- **Cloudflare Workers** запускают JS/TS в изолятах V8 без «холодного старта» контейнеров; статические файлы раздаются прямо из кэша CDN, даже не вызывая скрипт Worker.
- Тяжёлая конвертация на сервере упёрлась бы в лимиты Workers (CPU‑время, 128 МБ памяти, нет нативных библиотек вроде LibreOffice), поэтому сервер выполняет только лёгкие форматы (см. API).

```
Браузер
 ├─ UI (vanilla TS, без фреймворка)  — стартовая загрузка ≈ 30 КБ gzip
 ├─ Пул Web Worker'ов (до 4)          — конвертация документов/данных, сборка PDF
 │   └─ ядро src/core (pdf.js, pdf-lib, fflate) — грузится лениво, только когда нужно
 └─ Растровые операции (Canvas)        — изображения, PDF → PNG/JPG, редакторы
Cloudflare Worker
 ├─ Static Assets (+ _headers: CSP, кэш immutable)
 └─ /api/* — health, formats, convert (DOCX/MD/HTML/TXT/CSV/TSV/JSON/XLSX)
```

Ядро построено вокруг промежуточной модели документа (`src/core/model.ts`): читатели превращают байты в `Doc` (поток блоков) или `Workbook` (таблицы), писатели — обратно. Поэтому N входных × M выходных форматов не требуют N·M конвертеров.

| Модуль | Назначение |
|---|---|
| `src/core/readers/pdf.ts` | PDF → Doc: строки, абзацы, заголовки, списки, таблицы (по рамкам и столбцам), изображения |
| `src/core/readers/docx.ts`, `writers/docx.ts` | собственный разбор и генерация OOXML (стили, нумерация, таблицы, ссылки, изображения) |
| `src/core/writers/pdf.ts` | собственный движок вёрстки на pdf-lib: переносы, выравнивание, списки, таблицы с разрывом по страницам, ссылки, нумерация страниц |
| `src/core/readers/data.ts`, `writers/data.ts` | CSV (RFC 4180, автоопределение разделителя), JSON, XLSX |
| `src/core/readers/markdown.ts`, `html.ts` | Markdown (CommonMark/GFM‑подмножество), HTML без DOM |
| `src/core/pdf-tools.ts` | сборка PDF: изображения → PDF, страницы и пометки редактора |
| `src/app/` | интерфейс, пул воркеров, растровые операции, страницы редакторов |
| `src/server/index.ts` | Cloudflare Worker и API |

Шрифты для PDF — Liberation Sans (метрически совместим с Arial, кириллица) и DejaVu Sans Mono; они встраиваются подмножеством, только используемые начертания загружаются по требованию. Шрифт PT Sans был исключён: при субсеттинге через fontkit он теряет контуры глифов (есть регрессионный тест, сравнивающий растеризацию).

## Запуск

Требуется Node.js ≥ 22.13.

```bash
npm install
npm run dev        # разработка: http://localhost:5173 (Vite)
npm run preview    # сборка + локальный Cloudflare Worker (wrangler dev): http://localhost:8787
```

## Развёртывание на Cloudflare Workers

```bash
npx wrangler login   # один раз
npm run deploy       # сборка и публикация
```

Настройки — в `wrangler.jsonc`: статические файлы из `dist/`, SPA‑маршруты отдают `index.html`, Worker вызывается только для `/api/*`. Заголовки безопасности и кэширования — в `public/_headers`.

## API

Сервер конвертирует лёгкие форматы: **DOCX, Markdown, HTML, TXT, CSV, TSV, JSON, XLSX** (до 10 МБ). PDF и изображения обрабатываются только в браузере — API честно отвечает `422` с подсказкой.

```bash
curl https://<host>/api/health
curl https://<host>/api/formats            # все форматы и доступные преобразования

# тело запроса — файл; формат источника определяется автоматически
curl -X POST --data-binary @report.docx "https://<host>/api/convert?to=md&name=report.docx" -o report.md

# или multipart/form-data с полем file
curl -X POST -F "file=@sales.csv" "https://<host>/api/convert?to=xlsx" -o sales.xlsx
```

Ответ — файл с `Content-Disposition` (поддерживаются кириллические имена); предупреждения — в заголовке `X-Warnings` (JSON, URL‑encoded). Ошибки — JSON `{ "error": "...", "code": "..." }` с кодами 400/405/413/415/422/500. CORS открыт.

## Тестирование

```bash
npm test           # модульные и интеграционные тесты ядра (Vitest)
npm run test:e2e   # E2E в Chromium против собранного сайта под wrangler dev
npm run check      # сборка + все тесты
```

- **100 модульных/интеграционных тестов**: парсеры, полная матрица преобразований, круговые проверки DOCX/PDF/Markdown/HTML/XLSX, проверка результатов сторонними инструментами (LibreOffice открывает наши DOCX, `pdftotext` читает наши PDF, poppler‑растеризация подтверждает корректность встроенных шрифтов), разбор PDF из Chrome и LibreOffice, «враждебные» входные данные (zip‑бомбы, патологический Markdown, глубоко вложенный HTML, таблицы на 150 000 строк).
- **15 E2E‑сценариев** (Playwright): API и заголовки безопасности, конвертер (DOCX→PDF, PDF→Word, MD→PDF, PDF→JPG, PNG→JPG, XLSX→CSV, CSV→XLSX, пакетная обработка, объединение изображений), все три редактора с проверкой содержимого скачанных файлов, санитизация вставки, мобильная вёрстка без горизонтальной прокрутки.
- Тесты, использующие LibreOffice/poppler, автоматически пропускаются, если этих программ нет. Для E2E на своей машине: `npx playwright install chromium`.
- `BASE_URL=https://<host> npm run test:e2e` — прогон E2E против развёрнутого сайта.

## Ограничения

- **PDF → Word** — эвристическое восстановление структуры: многоколоночная вёрстка, плавающие надписи, сложные таблицы без рамок и без выровненных столбцов могут потребовать ручной правки. Распознавание сканов (OCR) не выполняется.
- **Word → PDF** — собственная вёрстка, а не движок Word: колонтитулы, сноски, многоколоночность, плавающие объекты и пользовательские шрифты не воспроизводятся (используется Liberation Sans). Символы вне покрытия шрифта (например, иероглифы) заменяются на «?» с предупреждением.
- Изображения EMF/WMF/TIFF внутри DOCX пропускаются (с предупреждением).
- **Редактор PDF** «впечатывает» пометки в страницу; существующий текст PDF не редактируется напрямую (используйте «замазку» + новый текст). Зашифрованные PDF редактировать нельзя.
- Старые форматы `.doc`, `.xls`, а также ODT/RTF/PPTX не поддерживаются.
- Нужен современный браузер (актуальные Chrome/Edge/Firefox/Safari): используются module‑воркеры, OffscreenCanvas, современная сборка pdf.js.
